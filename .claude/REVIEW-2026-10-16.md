## 三、关键发现

### P0-1 · 安装包内置了开发者的真实 API Key（密钥泄露）

**证据（已实测确认）**：

`electron-builder.yml` 用 `extraResources` 整体打包整个 `config/` 目录：

```yaml
extraResources:
  - from: config
    to: app.asar.unpacked/config
```

而 `config/user.json` 是**本机实际使用的配置**（开发版 `DATA_DIR` = 项目根），里面是真实密钥：

- `release\win-unpacked\resources\app.asar.unpacked\config\user.json` → 含 `sk-67a66…`(35)、`sk-pgvsn…`(51)
- **已安装的 `E:\software\XNOWPost`（v1.2.18）同样内置这两个 Key + 10 个账号的比特环境 ID**
- 打包产物中的 `user.json` 与仓库里的 `config/user.json` **SHA-256 完全一致**（即"打包 = 把开发机配置原样发出去"）
- `extraResources` 自**首次提交**（`e3ade62`）就存在，因此**历史上发布的每一个安装包都带这套 Key**
- **已公开泄露**：GitHub Releases 上共 **26 个安装包**已对外发布（`XNOWPost-Setup-*.exe`），累计 25 次下载；`latest.yml` 更被请求 **526 次**（说明存在通过自动更新拉取的实际装机量）

**影响**：任何下载过这些安装包的人都能解包拿到 Key 并盗用（费用算在开发者头上）；同时 10 个 TikTok 账号的环境 ID 一并泄露。**已必须视为公开泄露，务必立刻轮换。**

**附带同类泄露**：`electron/main.js:956-961` 还硬编码了**作者账号的 3 个比特浏览器环境 UUID**（`24056554bc0e479784f054c161670a53` 等），属于第二处"开发者专属数据进了代码"。`config:testBit` 甚至会 `POST /browser/open` 真的打开浏览器环境来做连通性测试。

**修复**：
1. 立即在 DeepSeek / 硅基流动后台**吊销并轮换这两个 Key**（已泄露的 Key 必须视为失效）。
2. `extraResources` 改为只放模板，例如把 `user.json` 排除：
   ```yaml
   extraResources:
     - from: config
       to: app.asar.unpacked/config
       filter: ["**/*", "!user.json", "!schedule.json", "!window-state.json"]
   ```
   或只白名单 `default.json` / `platforms.json` / `prompts/` / `tray-icon.png`。
3. 发布前加校验：构建脚本断言 `release/**/config/user.json` 不存在。

### P0-2 · FFmpeg 缺失 → 视频生成链路当前不可用

**证据（已实测确认）**：

```
$ node -e "import('./src/engine/tools.js').then(m=>console.log(m.findFFmpeg()))"
"ffmpeg"                        # ← 回退成裸字符串
$ ffmpeg -version
FAIL: Command failed: ffmpeg -version
```

`src/engine/tools.js:45` 在找不到时直接 `return 'ffmpeg'`，于是 `execSync('ffmpeg …')` 抛 ENOENT → 视频合成失败。全盘搜索仅在 `E:\software\Pixelle-Video-v0.1.15-win64\tools\ffmpeg\bin\ffmpeg.exe`（属于另一个软件）存在，不在 `findFFmpeg()` 的搜索范围内。

**连带静默 Bug**：`src/engine/voice.js:12` 用正则从 ffmpeg 路径推导 ffprobe：

```js
const ffprobe = FFMPEG.replace(/ffmpeg\.exe"?$/, 'ffprobe.exe').replace(/"/g, '');
```

当回退值是 `'ffmpeg'` 时正则不匹配，ffprobe **永不执行**，`parseFloat` 失败 → `return 5`，**每段配音都被当成 5 秒**，字幕与画面整体错位（而且不报错）。

**修复**：
1. 安装 FFmpeg（`winget install Gyan.FFmpeg` 或解压到 `C:\ffmpeg\bin`），并确认 `ffprobe.exe` 同目录。
2. 代码层加固：
   - 新增 `findFFprobe()`（与 `findFFmpeg()` 并列，取 `path.dirname(ffmpeg)/ffprobe.exe`）；
   - `findFFmpeg()` 找不到时**立即抛错**而不是回退裸字符串；
   - 引擎启动做一次 pre-flight（现在 `healthCheck()` 只探 PATH，winget 装的会被误报为"未安装"）；
   - `getAudioDuration` 的 5 秒兜底应记 warning，而不是静默返回。

### P0-3 · 发布器可能"假成功"，内容被永久标记为已发布

**证据（已读码确认）**：

1. `src/publisher/debug-trace.js:53-62` — `trace.step()` **吞掉异常且不重抛**：
   ```js
   } catch (err) { step.success = false; step.error = err.message; ... }   // 没有 throw
   ```
2. `src/publisher/tiktok.js:536-541` 主 Post 点击失败抛 `发布按钮不可见` → 被 step 吞掉，`posted` 仍为 `false`。
3. 兜底分支 `tiktok.js:583-614`：候选选择器全都没命中时，`page.evaluate` 可能一个按钮都没点到，但**第 611 行无条件 `posted = true`**。
4. 于是 `tiktok.js:616` 的 `if (!posted)` 成为**死代码**，永不触发告警。
5. `src/publisher/index.js:129` 只要 `publishToTikTok()` 正常 resolve 就**无条件** `markPublished(...)` 写 `.published`；而 `findUnpublished()`（`publisher/index.js:46`）此后永久跳过该内容。

**影响**：视频实际没发出去，系统却认为已发布 → **静默丢内容**，且不再重试。

**修复**：`trace.step` 失败时重抛（或让调用方检查 `step.success`）；兜底分支在没有任何按钮被点击时必须抛错；`.published` 只在确认跳转到 `/content` 后再写。

### P1-1 · 批量生成只跑第一条主题

**证据（已读码确认）**：

`src/renderer/views/Dashboard.vue:364-372`：

```js
await store.runEngine('auto', topic)
batchDone.value = i + 1
await refreshToday()
if (!store.status.running && i < topics.length - 1) break   // ← 恒为 true
```

`src/renderer/stores/app.js:44-48` 在 `finally` 里 `this.status.running = false`，所以 `await` 返回后 `running` **必然为 false** → 任何 ≥2 条的批量任务都在 `i=0` 就 break。

**修复**：让 `runEngine` 返回显式的取消标记（如 `cancelled`），用它判断，而不是读 `status.running`。

### P1-2 · 定时任务 ID 重复（数据已损坏 + Vue key 冲突）

**现状**（`config/schedule.json`，已确认）：账号 02 的 id 为 `2,101,101`；03 为 `3,102,102`；…08 为 `8,107,107` —— **7 个分组内存在重复 key**。

**根因**（来自审计）：`src/renderer/views/Schedule.vue:363` `let nextId = 100` 是**模块级计数器，每次组件挂载都重置**，`load()` 不与之对账；`addJob()` / `cloneJob()` 每次会话都重新发 100、101…；`schedule:save`（`electron/main.js:823-831`）不做任何校验。

**影响**：
- `Schedule.vue:70` 的 `:key="job.id"` 在同一父节点下出现重复 key → Vue 复用错节点，增删后开关状态/时间可能渲染到错误的卡片。
- **不会重复触发定时任务**：`scheduler.js:160-175` 从不读取 `job.id`；`globalIndex()`(:422) 用对象引用 `indexOf` 定位，所以编辑/删除目前仍指向正确对象 —— 属于隐患而非已发生的功能故障。

**修复**：`load()` 后 `nextId = Math.max(0, ...jobs.map(j => Number(j.id) || 0)) + 1`（或改用 `crypto.randomUUID()`）；在 `schedule:save` 内去重自愈；临时缓解可把 key 改成 `` `${job.id}-${gIdx}-${jIdx}` ``。

### P1-3 · 数据目录路径不一致（安装版会读/写到错误位置）

`XNOWPOST_DATA_DIR` 的约定只被部分模块遵守：

| 模块 | 表达式 | 判定 |
|---|---|---|
| `organizer.js:5-7` | 优先用 env | ✅ |
| `collector/index.js:16-17` | 优先用 env | ✅ |
| `src/index.js:157` | 优先用 env | ✅ |
| **`engine/dedup.js:5`** | `path.resolve('output/history.json')` | ❌ 写到安装目录 |
| **`analyzer/trends.js:4`** | `path.resolve('data/analytics.db')` | ❌ 与写入口径不一致 |
| **`scheduler.js:9,42,55`** | `ROOT = path.resolve('.')` 取 logs 与 TG 配置 | ❌ 与 `SCHEDULE_FILE`(用 DATA_DIR) 自相矛盾 |
| **`publisher/index.js:165`** | `path.resolve('config/user.json')` | ❌ 安装版读到内置配置而非用户配置 |

**影响**：安装版下 `scheduler` 的 TG 告警读的是"安装目录里的配置"（很可能读到打包时的旧 Key），告警看似发送实则失败；`publisher` CLI 同理；`dedup` 历史写到安装目录，去重失效。

**修复**：统一抽一个 `resolveDataDir()` helper，全模块改用它 —— 这正是 v1.1.4 修 collector 时做过的事，但漏了上面 4 处。

### P1-4 · 视频合成失败仍然"成功"退出

`src/index.js:72-77` 捕获 FFmpeg 异常后只打印警告，随后 `console.log('✅ 完成')` 并 **exit 0**。`scheduler.js:84` 因此记录 `✅ … 完成`，永不告警。半成品 session 目录也不会被清理，GUI 会把它当成有效产出。

**修复**：合成失败要置非零退出码（或返回状态），并写入 `FAILED` 标记 / 删除半成品目录。

### P1-5 · sql.js 持久化与迁移存在数据丢失风险

- **非原子全量重写**：`src/db.js:141`、`collector/index.js:150,229` 都是 `fs.writeFileSync(dbPath, db.export())` —— 直接截断重写整个库。进程被杀/超时（调度器 900s）恰好落在写入中间 → **整个历史库损坏或清空**。
- **迁移非事务**：`db.js:98-116` 的 `RENAME → CREATE → INSERT → DROP` 无事务；若在 RENAME 后中断，下次启动 `CREATE TABLE IF NOT EXISTS` 会建空表，`PRAGMA table_info` 又显示 `account` 已存在 → 迁移被跳过，**历史数据永久困在 `daily_stats_old` 里成为隐形数据**。
- **`openDB(dbPath, {readonly:true})` 的第二个参数被忽略**，只读是假象；且 sql.js 是内存态，**除 3 处显式 `export()` 外的任何写入都会静默丢失**。

**修复**：临时文件 + `rename` 原子替换；迁移包 `BEGIN/COMMIT` 并做幂等自愈（启动时检测 `daily_stats_old` 且新表为空则重放 INSERT）。

### P1-6 · 图片费用从未计入

`src/engine/cost.js:24` 的 `trackKolors()` **零调用点**，`image.js` 也没 import `cost.js`。因此 `cost.json`、控制台汇总（恒为 `Kolors ¥0.00`）和 GUI 全部**低报真实花费**。

### P1-7 · 命令注入面（模型输出 / 账号名拼进 cmd.exe）

`src/engine/voice.js:45-49` 把 **LLM 生成的文案**经 `\"` 转义后拼进 shell 字符串：

```js
const safeText = text.replace(/"/g, '\\"')...
execSync(`${EDGE_TTS} … --text "${safeText}" …`)
```

但 `cmd.exe` **不把 `\` 当转义符**：`\"` 仍然会闭合引号，`%VAR%`、`&`、`|`、`>` 均有效 → 文案里出现英文引号或 `%` 就会破坏合成甚至注入。同类问题：`scheduler.js:131`（`job.account`）与 `:119`（`job.collectAccounts` 未加引号）。

**修复**：一律改 `spawnSync(exe, [args...], { windowsHide: true, shell: false })`。

### P1-8 · Electron 主进程高危缺陷（IPC / 生命周期 / 安全）

主进程共 **35 个 `ipcMain.handle`，0 个 `ipcMain.on`**。安全基线**总体合格**：`contextIsolation: true`、`nodeIntegration: false`、未关闭 `webSecurity`、preload 只暴露 `contextBridge`（无裸 `ipcRenderer` 透传）、**全项目无 `shell: true`**（`topic`/`accounts` 走 argv 数组，不可注入）、`shell:openExternal` 有协议白名单。

但存在以下问题：
